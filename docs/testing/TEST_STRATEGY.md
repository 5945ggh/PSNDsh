# 薄测策略

> 状态：当前阶段基线  
> 原则：前端风格和部分交互仍在探索，只测试会导致数据损坏、安全越界或核心闭环失效的内容。

## 1. 当前目标

- 用少量稳定测试锁住领域不变量。
- 避免在 UI 尚未定稿时编写大量脆弱组件测试和截图基线。
- 每个核心模块至少有一个成功路径和一个关键失败路径。
- 测试数据使用固定时间和显式 `Asia/Shanghai`，避免依赖执行机器当前时间。

## 2. 必须有的单元测试

### 注册能力

- `first-user` 在零用户时开放、有用户后关闭。
- `open` 始终开放，`closed` 始终关闭。
- 非法 `REGISTRATION_MODE` 拒绝启动配置。

### 条目树

- 防止把节点移动到自身或后代之下。
- 父节点聚合等于直接投入加全部后代直接投入。
- 移动子树后聚合按当前树重新计算。

### 专注区间

- 拒绝专注会话重叠。
- 允许日程和专注重叠。
- 片段完整覆盖会话且互不重叠。
- 未分配空隙转为未关联片段。
- 拆分和重新归属不改变总时长。

### 时间边界

- `23:30–00:30` 在相邻两日各计 30 分钟。
- 同一求交算法至少覆盖一个周界和一个月界样例。

### 周结转

- 活跃、未完成、未归档且在上一周计划中的条目被结转。
- 已完成、已归档或已移出上一周计划的条目不结转。
- 同一周重复执行结转不产生重复关系。

## 3. 必须有的数据库或服务集成测试

- 并发开始专注时，每个用户最多一条活动记录。
- `open` 注册模式下，账号 A 无法读取、修改或导出账号 B 的对象。
- 归档或永久删除条目不会删除历史专注；关系仍可解释。
- 服务重启语义下，活动计时仍可通过持久化记录恢复。
- JSON 导出包含规定业务数据且排除密码、会话和服务端密钥。

## 4. 最小浏览器测试

只保留三条：

1. 首次注册、登录、修改昵称和邮箱、退出。
2. 创建条目并加入本周，开始无归属专注，结束后拆分归属，统计出现正确结果。
3. 手动补录跨日专注，在周历看到与课程重叠，首页仍可用且天气失败正确降级。

前端样例阶段这些流程可以由 mock 驱动；正式后端接入后再切换为真实 API。

## 5. 暂不测试

- 全组件快照测试。
- 每个表单字段组合的穷举。
- 全浏览器矩阵。
- 像素级视觉回归。
- 大规模性能和压力测试。
- 所有 ICS recurrence 变体。
- 天气和名句真实上游的在线集成测试。

## 6. 何时扩展

出现以下情况时增加相应测试：

- 前端样例被批准并形成稳定设计 token：增加关键页面视觉烟测。
- 选定认证库：增加其会话过期、撤销和 Cookie 安全测试。
- 选定 ICS 库：增加真实课程文件 fixtures。
- 引入 Agent、公开 API 或 MCP：增加授权、数据最小化和审计测试。
- 从 SQLite 迁移或支持更高并发：增加事务与迁移验证。
