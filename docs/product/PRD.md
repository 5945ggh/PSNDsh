# 个人面板 PRD

> 状态：需求基线已形成，技术设计已起草，待前端样例校准  
> 版本：0.3
> 日期：2026-07-22

## 1. 产品概述

### 1.1 产品定义

个人面板是一套部署在内网服务器、以个人使用为主的 Web 应用。它将每周计划、可嵌套事项、课程或计划日历、真实专注时间和多尺度回顾统一起来，帮助用户回答四个问题：

1. 今天与本周准备做什么？
2. 现在应该从哪里开始？
3. 时间实际上花到了哪里？
4. 最近完成了什么、仍有什么临期或受阻？

系统未来可以向 Agent 提供受控的结构化个人上下文，但首版不实现 Agent、LLM 或 MCP 接入。

### 1.2 背景与问题

现有每周 Markdown 工作流已经证明以下能力有价值：

- 按周组织和回看计划；
- 使用树形层级表达学科、项目和具体事项；
- 将未完成事项结转到下一周；
- 同时保留勾选状态、自由批注和归档语境。

其主要成本是每周手动复制、结构难以统计、实际投入无法自动连接、日历与时间分析分散。通用待办软件通常又会强迫用户过早分类，或将时间记录完全从属于具体任务，无法自然表达长期学习方向和未分类活动。

### 1.3 产品目标

- 保留 Markdown 工作流的树形表达力和低约束记录方式。
- 自动完成跨周延续、临期提醒和历史归档。
- 同时承载计划时间与实际专注事实。
- 允许实时计时、事后补录、拆分和暂不分类。
- 提供可信的日、周、月投入统计。
- 形成结构化、可备份、可扩展的数据基础。

### 1.4 产品原则

- **事实先于分类**：可以先记录发生的时间，稍后整理归属。
- **统一而不抹平语义**：方向、项目与待办共享条目模型，但保留完成行为差异。
- **低摩擦优先**：常用操作不能要求填写大量字段。
- **计划与事实并行**：课程或计划描述背景，专注描述真实活动，二者允许重叠。
- **本地与隐私优先**：默认只在用户控制的内网环境中处理个人数据。
- **成熟实现优先**：认证、密码哈希、校验等安全敏感能力采用成熟库。
- **可解释统计**：直接投入、聚合投入、未关联投入必须能够区分。

## 2. 用户与使用环境

### 2.1 目标用户

首版面向个人使用，默认只创建一个账号，但注册开放策略由部署环境变量控制。即使部署者选择开放注册，各账号的数据也必须严格隔离；首版不提供账号间协作、共享、邀请、管理员后台或角色权限。

所有业务对象均具有明确的用户归属。服务端必须验证对象归属，不能因为默认部署只有一个账号就省略访问边界。

### 2.2 主要设备

- 桌面浏览器：完整规划、周历与统计分析。
- 手机浏览器：查看今日信息、快速开始或结束专注、补记事项。

首版为响应式 Web，不开发原生客户端。

### 2.3 部署环境

- 可部署在个人控制的内网服务器。
- 支持稳定重启与持久化存储。
- 应提供明确的配置、升级、备份与恢复说明。
- 天气能力需要服务器访问公网；不可用时核心功能仍正常。季节名句使用随应用发布的本地内容包，运行时不依赖公网。

### 2.4 时间口径

- 首版使用实例配置 `effectiveTimezone`，默认值为 `Asia/Shanghai`，设置页暂不提供修改入口。
- 所有绝对时间以 UTC 或带时区的标准时间戳持久化；日期、星期、周界、月界、截止时间和统计均按 `effectiveTimezone` 解释。
- 每周从 `effectiveTimezone` 下的周一 `00:00` 开始。
- ICS 单次定时事件带时区时按文件时区解析；缺少时区时按 `effectiveTimezone` 解析。重复事件带 UTC 或 IANA `TZID` 时按文件时区解析；未声明时区时按 `effectiveTimezone` 解释其墙上时间，不依赖宿主时区。
- JSON 导出同时包含标准时间戳和实例时区元数据。
- 实例产生业务数据后，首版不支持直接修改 `effectiveTimezone`；变更必须通过后续明确的数据迁移流程完成。

## 3. 核心概念

### 3.1 用户 User

| 字段 | 要求 |
|---|---|
| 账号 | 必填、唯一，注册后用于登录 |
| 密码凭据 | 由成熟认证库安全管理，不保存明文 |
| 昵称 | 可选；未设置时可回退显示账号 |
| 邮箱 | 可选；只做成熟库提供的格式校验 |
| 创建与更新时间 | 必须记录 |

注册只填写账号、密码和确认密码。昵称和邮箱在设置页中编辑。首版不验证邮箱归属，也不发送任何邮件。

### 3.2 条目 Entry

条目是计划管理的统一核心对象，可表达课程方向、长期技能、阶段项目、任务分组和具体待办。

| 字段 | 说明 |
|---|---|
| 标题 | 必填 |
| 描述或批注 | 可选，支持多行文本 |
| 父条目 | 可选，形成树形结构 |
| 完成模式 | `ongoing` 持续型；`completable` 可完成型 |
| 状态 | 活跃、暂停、已完成、已归档 |
| 截止时间 | 可选，仅在需要时启用 |
| 排序 | 同级手动排序 |
| 创建、完成、归档时间 | 按状态记录 |

规则：

- 所有条目都可以直接承接专注时间。
- `ongoing` 条目不显示完成复选框，可暂停或归档，不能进入“已完成”状态。
- `completable` 条目可完成；未完成且超过截止时间时为逾期。
- 截止时间不决定条目类型；持续型条目也可通过子条目表达阶段目标。
- 完成或归档父条目不得静默改变子条目；界面需要提示仍活跃的后代并让用户显式处理。
- 常规删除采用软删除或等价机制，不能破坏历史专注记录。

### 3.3 周计划 WeekPlan

周计划表达“某一周主动纳入视野的条目”，而不是复制条目本身。

| 字段 | 说明 |
|---|---|
| 周起始日 | 默认周一，按实例 `effectiveTimezone` 计算 |
| 纳入条目 | 指向条目的关系 |
| 本周排序 | 不影响全局树排序 |
| 本周备注 | 可选，用于保留类似 Markdown 的周语境 |
| 纳入来源 | 手动加入或自动结转 |

规则：

- 用户可将任意条目纳入本周。
- 新一周开始时，上一周仍活跃且未完成、未归档的纳入条目自动进入新周。
- 自动结转不复制条目，不丢失过去每周的纳入关系。
- 已完成或归档条目默认不结转，但仍出现在历史周。
- 持续型条目只要仍活跃并已纳入上周，也可自动结转。
- 用户可以从本周移除条目而不归档或删除它。

### 3.4 专注记录 FocusSession

专注记录描述实际发生的一段活动时间，是独立持久的事实。

| 字段 | 说明 |
|---|---|
| 开始与结束时间 | 必填；活动计时中结束时间为空 |
| 记录方式 | 实时计时或手动补录 |
| 备注 | 可选，描述做了什么 |
| 成果 | 可选，描述产生了什么结果 |
| 创建与更新时间 | 必须记录 |

规则：

- 同一用户同一时刻最多有一个活动计时器。
- 有效专注记录之间不得重叠；补录冲突时必须要求调整或拆分。
- 允许没有任何条目归属的专注记录。
- 允许修改备注、成果、时间范围和归属。
- 条目改名后，历史专注显示条目当前名称，不冻结旧名称版本。
- 条目归档后关联仍保留并显示归档状态。
- 条目永久删除后专注仍保留，原归属转为可解释的已删除或未关联状态。

### 3.5 专注片段 FocusSegment

一次专注可以拆成若干连续或不连续片段，以表达不同归属。

| 字段 | 说明 |
|---|---|
| 所属专注记录 | 必填 |
| 片段开始与结束 | 位于专注记录范围内 |
| 直接归属条目 | 可选；为空时属于未关联桶 |
| 片段备注 | 可选；默认可继承会话备注 |

约束：

- 同一专注记录内的片段不得重叠。
- 一个时间点只能直接归属一个条目或未关联桶。
- 所有片段的并集必须完整覆盖专注记录，不允许留下不计入统计的时间空洞。
- 用户没有显式分配的区间自动成为未关联片段；未拆分时，整段即为一个片段。
- 拆分和重新归属不得改变专注记录的总时长，只改变各归属桶的时长。
- 父节点统计由子节点递归聚合，不通过重复归属生成。

### 3.6 日程块 ScheduleBlock

日程块表达课程、计划安排或其他时间背景。

| 字段 | 说明 |
|---|---|
| 标题 | 必填 |
| 类型 | 课程、计划、其他 |
| 开始与结束时间 | 必填 |
| 重复规则 | 可选，支持课程周重复 |
| 有效日期范围 | 可选，适配学期或假期 |
| 地点、说明、颜色 | 可选 |
| 来源 | 手动创建或文件导入 |

日程块可以与专注记录重叠。系统不得把这种重叠作为数据错误，也不得将其自动解释为用户未参与课程。

## 4. 功能需求

### 4.1 注册、登录与会话

#### 注册

- 输入账号、密码、确认密码。
- 校验账号唯一性、密码要求和两次密码一致性。
- 不要求昵称、邮箱或验证码。
- 注册策略由服务端环境变量 `REGISTRATION_MODE` 控制，设置页不提供修改入口。
- `first-user`：默认值；仅在用户表为空时允许注册，首次成功注册后自动关闭。
- `open`：持续允许创建彼此数据隔离的账号。
- `closed`：始终关闭注册；已有账号仍可登录。
- 非法配置值必须在服务启动时明确报错，不能静默回退为开放注册。
- 前端注册入口根据服务端返回的注册能力显示或隐藏，但服务端注册接口始终独立执行同一策略校验。
- 修改环境变量后通过重启应用生效，不在数据库或用户设置中保存一份可能冲突的开关。
- 注册成功后进入登录态或登录页，具体采用认证库推荐的安全流程。

#### 登录与退出

- 使用账号和密码登录。
- 提供明确退出入口。
- 会话 Cookie 使用合理的 `HttpOnly`、`SameSite` 和生产环境安全配置。
- 对登录尝试应用成熟库或服务端限流机制。

#### 实现约束

- 优先评估 Better Auth 等成熟方案与最终技术栈的适配性。
- 不自行实现密码哈希算法、会话加密或邮箱正则。
- 所有输入在服务端使用成熟 schema 校验库再次验证。

### 4.2 设置页

首版提供可访问的设置页，而不是只预留路由。

首版内容：

- 查看账号，默认不可在界面中修改。
- 修改昵称。
- 修改或清空邮箱。
- 邮箱使用成熟验证器做基础格式校验。
- 明确提示邮箱不会收到验证信，也不用于找回密码。

结构上预留后续配置分区，例如个人资料、界面、日期时间、外部数据、数据管理和 Agent 接入；未实现的分区不展示伪控件。

### 4.3 首页

首页用于快速定向，不承载完整编辑工作流。

首版信息：

- 基于昵称或账号的简短欢迎信息。
- 当前日期、星期和时间。
- 当地天气摘要；地点首版可由实例配置提供。
- 按季节选择的古诗文名句及出处。
- 当前或下一项课程、计划。
- 当前活动专注及快速结束入口。
- 今日纳入计划的未完成条目。
- 即将到期和已逾期条目。
- 今日已专注时长与最近一周简要趋势。

天气请求需要缓存、超时和降级；失败时隐藏对应数据或展示最近缓存，不能阻塞首页其余内容。季节名句从本地内容包读取，不应进入首页网络请求或降级路径。

### 4.4 条目与树形管理

- 创建顶层条目或任意条目的子条目。
- 编辑标题、描述、完成模式、状态和截止时间。
- 同级排序和跨父节点移动。
- 完成、重新打开、暂停、恢复、归档和恢复归档。
- 从条目详情查看直接投入、聚合投入、子条目和相关专注时间线。
- 从树形视图快速新建子条目。
- 在待办视图中聚合展示活跃、可完成且未完成的条目。
- 在持续视图中突出活跃的持续型条目。

删除属于低频危险操作，应在归档之后提供并明确说明历史专注不会被删除。

### 4.5 周计划与自动结转

- 查看任意一周的计划。
- 将条目加入本周、排序、移出本周。
- 编辑本周备注。
- 在当前周中完成或归档条目。
- 新周首次访问或后台周界处理时，幂等地执行结转。
- 对自动结转条目标记来源，用户可从本周移除。
- 历史周展示当时纳入的条目，并使用其当前标题与当前状态；首版不保存完整标题版本。

### 4.6 实时专注

- 可从全局入口或条目入口开始专注。
- 允许不选条目直接开始。
- 任意时刻只有一个活动计时器。
- 页面刷新、重新登录或服务重启后仍能恢复活动状态。
- 活动期间持续显示经过时间，但真实时长由服务端时间戳计算。
- 结束时可快速保存，也可填写备注、成果并拆分归属。
- 不能删除正在计时的关联条目；可以先结束专注或解除归属。

首版不强制填写成果或 handover prompt，以免增加记录阻力。

### 4.7 手动补录与编辑

- 输入开始时间、结束时间、备注、成果和可选归属。
- 检测与已有专注记录的重叠。
- 支持调整原记录、取消补录或将合法区间拆开后保存。
- 支持编辑已有专注的时间和文本信息。
- 支持将一段专注拆分为多个片段并分别归属。
- 支持将片段重新归属或变为未关联。

### 4.8 周历

周历是计划与事实的联合视图。

- 支持上一周、下一周和返回本周。
- 按实例 `effectiveTimezone` 展示七日时间网格。
- 日程块和专注记录使用独立视觉轨道或图层。
- 重叠时两者均可辨认、悬停或点击，不相互遮盖主要信息。
- 课程或计划可与课程或计划重叠；专注可与日程重叠。
- 专注记录之间不允许重叠。
- 点击日程查看详情；点击专注查看或编辑记录。
- 支持手动新增单次或重复日程块。
- 首版支持一种离线、单向批量导入方式；优先采用标准 ICS 文件。
- ICS 导入采用“选择文件 -> 预览 -> 确认”两阶段流程；确认时只写入当前账号选中的、服务端已验证的候选项。
- 单次定时事件直接导入；带明确 UTC 或 IANA `TZID` 的重复事件在未来 180 天展开为具体日程，保留窗口内的 DST、异常日期和单次覆盖结果；未声明时区的重复事件按 `effectiveTimezone` 展开。
- 全天事件及其他无效事件在预览中明确过滤；窗口外的重复不会自动延续，也不进行外部日历回写或持续同步。
- 每次实际写入都会形成一个 ICS 导入批次并保留文件名；预览会按当前账号已有的 `sourceUid` 标记重复来源并默认跳过，服务端确认时再次防止重复写入。日历页可以按批次删除该批次的全部实例。
- 首版不向外部日历回写，也不持续同步。

### 4.9 时间统计

提供日、周、月三种固定尺度，并允许选择具体区间。

核心指标：

- 总专注时长。
- 未关联时长。
- 按顶层条目及子树分布。
- 节点直接投入与聚合投入。
- 每日趋势。

聚合定义：

```text
aggregate(node, range)
  = direct(node, range)
  + sum(aggregate(child, range))
```

统计规则：

- 总专注时长等于所选范围内全部片段时长之和，也等于各条目直接投入加未关联投入之和。
- 跨越日、周、月边界的专注片段按实际重叠时长切分。
- 例如 `23:30–00:30` 的片段在相邻两日分别计入 30 分钟。
- 改变片段归属后，历史统计立即重算。
- 移动条目后，历史聚合按当前树结构重算。
- 暂停、完成或归档不会从历史统计中移除投入。
- 未关联时长不得被隐藏在总时长差额中。

### 4.10 外部信息

#### 天气

> 首版范围：不配置真实天气。首页保留不阻塞的不可用状态；待实例或用户级位置模型和设置页面设计明确后，再启用本节的上游、缓存和降级要求。

- 使用无需付费或具有足够免费额度的来源。
- 位置由实例配置提供，后续可迁移至用户设置。
- 单次服务端请求超时上限为 3 秒；成功结果作为新鲜缓存保存至少 30 分钟。
- 请求失败时可展示不超过 24 小时的旧缓存并标记更新时间；没有缓存时展示轻量不可用状态或隐藏天气内容。
- 同一缓存有效期内不得重复请求上游。
- 显示温度、天气状况和必要的短时提示即可。
- 请求上游时不得携带账号、条目、日程或专注数据。

#### 季节名句

- 根据当前日期和季节选择名句。
- 名句通过受控的预抓取流程从古诗文相关公开来源取得，优先评估古诗文网，生成随应用发布的版本化本地内容包；应用运行时不得向名句来源发起请求。
- 在预抓取流程就绪前，可以发布人工审核的最小本地内容包；人工内容同样必须记录作者、作品、来源地址和内容包版本。
- 每条内容保存名句、作者、作品、来源地址和内容包版本，便于追溯和替换。
- 内容包至少覆盖四季，首次离线启动即可展示。
- 数据包使用一个季节一个 JSON 文件的 `1.0` 格式，字段与发布校验规则见 [季节名句数据包](../content/QUOTATION_DATA_PACK.md)。
- 预抓取可以由发布前的脚本或受控运维任务执行，不属于用户请求链路；抓取、解析、去重和内容校验完成后才可更新内容包。
- 预抓取必须遵守来源站点可接受的访问方式，采用克制的频率和超时；请求不得携带任何用户数据。
- 预抓取失败时继续使用上一个已发布内容包，不影响已部署实例的首页展示。

### 4.11 数据管理

- **结构化 JSON 导出**用于可读快照和未来迁移，覆盖非敏感用户资料、条目及归档状态、周计划、日程、专注记录和全部片段；首版不承诺从该 JSON 直接导入恢复。
- JSON 导出不包含密码哈希、会话令牌、服务端密钥、天气缓存或随应用发布的名句内容包。
- **数据库级备份与恢复**用于同版本灾备，覆盖凭据、业务数据、活动计时器、归档记录及为历史关系保留的软删除记录。
- 文档必须说明备份文件范围、创建方式、敏感性、保存位置建议和恢复步骤。
- 恢复以相同应用版本的空实例为目标；恢复后必须执行数据完整性检查和代表性查询核对。
- 数据结构使用稳定 ID 和明确时间戳，为未来只读 API 或 MCP 适配保留基础。

## 5. 信息架构

建议一级导航：

| 页面 | 主要职责 |
|---|---|
| 首页 | 今日定向、提醒、当前专注和摘要 |
| 计划 | 条目树、本周计划、待办和持续方向视图 |
| 日历 | 课程或计划与专注记录的周历叠加 |
| 统计 | 日、周、月时间投入分析 |
| 设置 | 资料、未来偏好和数据管理入口 |

活动计时器属于全局状态，应在所有主要页面保持可见和可结束，但不得遮挡页面核心内容。

## 6. 关键用户流程

### 6.1 晨间定向

1. 用户登录或打开已有会话。
2. 首页展示今日课程或计划、当前周条目、临期事项和昨日或本周投入摘要。
3. 用户进入计划或日历查看细节，也可直接开始无归属专注。

### 6.2 完成一次专注

1. 用户从全局或某条目开始计时。
2. 系统记录服务端开始时间并维持唯一活动状态。
3. 用户结束计时。
4. 用户可以直接保存，或填写备注、成果、拆分片段和调整归属。
5. 日历与统计立即反映新记录。

### 6.3 事后补录

1. 用户在日历空白处或专注记录入口选择补录。
2. 输入时间范围和可选内容。
3. 系统检查与已有专注是否重叠。
4. 保存后可继续拆分与归属。

### 6.4 跨周延续

1. 新周开始后系统创建或加载本周计划关系。
2. 将上一周仍活跃、未完成、未归档的纳入条目幂等结转。
3. 用户查看结转来源，并按本周需要移除、排序或新增条目。
4. 上一周仍保持可回看。

## 7. 非功能需求

### 7.1 安全

- 使用成熟认证与密码哈希实现。
- 服务端验证所有输入和对象归属。
- 防止跨用户对象访问，即使首版只有一个实际用户。
- 对登录和写操作采用合理的 CSRF、Cookie 和限流防护。
- 日志不得记录密码、会话令牌或完整敏感请求体。
- 第三方天气请求与名句预抓取请求均不得携带个人计划或专注数据。

### 7.2 可靠性

- 写操作具备明确成功或失败反馈。
- 自动结转必须幂等。
- 活动计时以持久化时间戳为准，不能依赖浏览器持续运行。
- 外部服务故障与核心记录功能隔离。
- 所有绝对时间统一持久化为 UTC 或带时区时间戳，并按实例 `effectiveTimezone` 展示和统计。

### 7.3 性能

- 常规首页、周计划和周历在个人规模数据下应快速响应。
- 树形聚合应避免明显的逐节点查询放大。
- 天气数据必须缓存，不在每次页面渲染时重新请求；名句使用本地内容包，不在应用运行时抓取。

### 7.4 可用性与无障碍

- 核心操作支持键盘访问和清晰焦点状态。
- 状态不能只依赖颜色表达。
- 手机宽度下文字、日历和计时控件不得互相遮挡。
- 删除、永久清除等危险操作必须显式确认。

### 7.5 可维护性

- 避免为未来 Agent 功能提前建设复杂抽象。
- 核心领域逻辑与天气适配、名句内容预处理和认证适配层分离。
- 数据迁移可重复验证并有备份前置说明。
- 新依赖需要说明用途、维护状态和许可证风险。

## 8. 首版非目标

- 邮件发送、邮箱验证、找回密码。
- OAuth、企业登录、双因素认证。
- 多用户协作、共享计划和角色权限。
- Agent 主动修改数据或自动执行计划。
- MCP Server、LLM 对话、自动摘要和智能分类。
- 自动生成计划、推荐下一步或评判时间使用好坏。
- 外部日历、教务系统的持续或双向同步。
- Markdown 历史批量导入与双向同步。
- 条目全文搜索和相邻周期环比分析。
- 完整对象版本历史、审计回放和历史树快照。
- 原生 iOS、Android、macOS 或 Windows 客户端。
- 打卡连续天数、积分、排行榜和社交功能。

## 9. 成功标准

首版投入实际使用后，应满足：

- 用户无需继续手动复制每周 Markdown 即可完成本周管理和结转。
- 开始无归属专注不超过一次主要操作，结束后可直接保存。
- 事后补录和重新归属不会破坏历史时长。
- 用户能够从周历同时看清计划背景与实际投入。
- 任一统计数字都能追溯到具体专注片段，并解释直接与聚合差异。
- 服务器或外部接口短暂失败不会造成专注或计划数据丢失。
- 用户可以完成结构化 JSON 导出，并按文档在空实例完成一次数据库级备份恢复。
- 连续使用四周后，历史周、当前条目和时间统计仍保持可理解性。

## 10. 验收清单

### 账号与设置

- [x] 只填写账号、密码、确认密码即可注册。
- [x] `REGISTRATION_MODE=first-user` 时，首次注册成功后页面入口消失，直接调用注册接口也被拒绝。
- [x] `REGISTRATION_MODE=open` 时可创建第二账号，两个账号无法读取、修改或导出彼此的数据。
- [x] `REGISTRATION_MODE=closed` 时注册页面不提供入口，直接调用注册接口也被拒绝，已有账号仍可登录。
- [x] 非法 `REGISTRATION_MODE` 会阻止服务启动并给出明确配置错误。
- [x] 重复账号、弱或非法密码、两次密码不一致得到明确错误。
- [x] 用户可以登录、退出，并在刷新后维持合法会话。
- [x] 设置页可修改昵称、设置或清空邮箱。
- [x] 非法邮箱被拒绝，合法邮箱不触发任何邮件流程。

### 条目与周计划

- [x] 可创建、移动、排序和编辑嵌套条目。
- [x] 持续型与可完成型条目的状态行为正确。
- [x] 截止提醒、逾期判断和重新打开正确。
- [x] 条目可加入或移出本周，不影响条目本身。
- [x] 新周只结转符合条件的条目，重复执行不会产生重复关系。
- [x] 历史周仍可查看当时纳入的条目。

### 专注

- [x] 任意时刻只能运行一个计时器。
- [x] 无归属计时、关联条目计时和手动补录均可用。
- [x] 刷新、重新登录和服务重启不会丢失活动计时事实。
- [x] 重叠专注被阻止并给出可修正反馈。
- [x] 专注可拆分、重新归属或变为未关联。
- [x] 任意拆分后片段完整覆盖原专注区间，未分配空隙自动计入未关联，总时长保持不变。
- [x] 归档或删除条目不会删除专注记录。

### 日历与统计

- [x] 周历可区分日程轨道和实际专注轨道。
- [x] 日程与专注重叠时二者仍可辨认和操作。
- [x] 支持手工日程与首版选定格式的单向导入。
- [x] 日、周、月统计按边界正确切分时长。
- [x] 在 `Asia/Shanghai` 下，`23:30–00:30` 的专注在相邻两日各计 30 分钟，周界和月界采用同一重叠算法。
- [x] 父节点聚合等于自身直接投入加所有后代直接投入。
- [x] 未关联时长单独可见，且总时长不重复计算。

### 首页与可靠性

- [x] 首页展示今日安排、当前专注、待办、临期或逾期和投入摘要。
- [x] 时间和季节名句按设计显示；天气明确不纳入首版，首页保持非阻塞不可用状态。
- [x] 断网时首页仍从本地名句内容包展示季节名句；应用运行时不请求名句上游。
- [x] JSON 导出覆盖规定业务数据且不含凭据、会话与服务端密钥。
- [x] 将含条目树、历史周、日程、活动计时器、拆分专注、未关联时长、归档和软删除关系的数据集备份，并在同版本空实例恢复后核对关键查询一致。

## 11. 后续演进方向

以下方向只用于保护扩展空间，不纳入首版排期：

- 用户级天气地点、时区、周起始日和界面偏好。
- 条目标题与描述搜索。
- 相邻周期投入比较与更丰富趋势分析。
- 更丰富的周期计划、复盘和趋势分析。
- 只读个人上下文 API。
- 经用户显式授权的 MCP 资源与工具。
- Agent 可读取的“当前状态”摘要，包括当前专注、本周计划、近期投入和下一步行动。
- 受审计、可撤销、最小权限的 Agent 写操作。

未来 Agent 接入必须先定义数据最小化、读取范围、授权时效和操作审计，不能因为数据已经结构化就默认全部暴露。

## 12. 已采用的默认决策

这些决策用于让 PRD 可执行，用户审阅时可直接修改：

- 每周从周一开始。
- 注册策略由 `REGISTRATION_MODE=first-user|open|closed` 控制，默认 `first-user`，只通过部署环境变量修改。
- 首版实例 `effectiveTimezone` 默认为 `Asia/Shanghai`，产生数据后不直接修改。
- 同一用户的专注记录不得互相重叠。
- 活动计时器只能有一个。
- 专注片段必须完整覆盖会话，未分配区间自动归入未关联桶。
- 首版邮箱可为空且不验证归属。
- 首页天气地点先由实例配置提供。
- 课程批量导入优先采用单向 ICS 文件；导入批次可整体删除，适合替换学期课表或切换假期作息。
- ICS 导入文件上限为 1 MiB，预览在 15 分钟后失效且只能由创建它的账号确认一次。
- 历史周显示条目的当前标题与状态，不保留标题版本。
- 移动条目后，历史聚合按当前树结构计算。
- 删除以归档为主要路径，永久删除仍保留专注事实。
- 专注结束时备注与成果均非必填。
